## Что реализовано

- Направление → Предмет → Курс преподавателя → Тема → Занятие → Задания. Курсы имеют независимые ID и поле преподавателя.
- Задания создаются внутри конкретного занятия. Из агрегированного списка и глобального добавления требуется явный выбор занятия; тема определяется по занятию. Путь в списке включает занятие.
- Старые задания без sessionId сохранены в отдельном списке «Требуют привязки», в том числе при архивном родителе. Их можно редактировать, экспортировать и затем привязать без случайного выбора занятия.
- Дерево сворачивается независимо на пяти уровнях, состояние сохраняется. При создании записи раскрываются её родители. В редакторе существующего занятия также показаны его задания с процентами и переходами.
- Перемещение занятия между темами обновляет совместимые topicId связанных заданий. Архив родителя скрывает потомков, восстановление сохраняет собственный архив дочерней записи. Есть удаление из архива.
- Удаление занятия удаляет именно его задания; каскады остальных уровней сохраняют целостность. Подтверждение показывает количество записей. Копия данных создаётся до удаления.
- Чистая, детерминированная и идемпотентная миграция v1 → v2: исходные записи и ID сохраняются, для курсов создаются предметы «Без предмета». Сначала предлагается скачать исходный JSON, затем пользователь запускает перенос.
- Перед миграцией, импортом и удалением сохраняется отдельная точная локальная копия. Сбой резервирования или основной записи не перезаписывает исходный документ. Ранее сделанные резервные копии сохранены и доступны в настройках.
- Проверка типов, ID (включая шаги и ссылки), родителей, реальных дат, длительности, URL и согласованности прогресса/completedAt перед записью. Неизвестная версия и повреждённый JSON не заменяются стартовыми данными; исходная строка доступна для скачивания.
- Автосохранение корректных изменений существующей записи через 550 мс, устойчивые ID шагов/ссылок, сохранение черновика при ошибке. Исправлено ложное повторное состояние «Изменения» после ухода с уже сохранённого текстового поля.
- Четыре вида календаря, переходы дат и создание из слота; занятия через полночь видны на обоих днях, включая «Сегодня». Дедлайны отображаются во всех видах, просрочка применяется только к невыполненным заданиям. Месячный календарь имеет «Ещё N».
- Доступны все экраны навигации; функции шагов 2–3 явно обозначены как будущие. Полноэкранный мобильный редактор, клавиатурное сворачивание, фокус внутри редактора, возврат фокуса, предупреждение при несохранённом вводе.

## Ограничения и решения

- На физическом iPhone и в установленном Safari проверка не проводилась. WebKit Linux не выдаётся за iOS Safari. Оценка экранной клавиатуры и удобства на устройстве остаётся владельцу; функциональные сценарии выполнены разработчиком.
- file:// в браузере рабочего окружения блокируется ERR_BLOCKED_BY_ADMINISTRATOR. Функциональные прогоны и проверка автономного HTML проведены через изолированный HTTP-origin; работу файлового просмотрщика iOS не обещаем.
- Абсолютная атомарность одновременных записей localStorage несколькими вкладками невозможна. Поддержана одна редактирующая вкладка; обнаруженный конфликт блокирует изменения. Тест реального события storage пройден, строгая гонка compare-and-swap не заявляется безопасной.
- Локальные копии в том же браузере не защищают от очистки браузера. Перед публикацией нужно сохранить актуальный внешний JSON, который пользователь уже умеет экспортировать. Старые защитные ключи копий сохранены согласно указанию не удалять данные; основное состояние по-прежнему хранится одним документом studyPlanner:v1.
- Повторения, таймер, главная, цели, аналитика, объединение импорта, Undo и темы не объявляются готовыми: они относятся к последующим шагам плана.
