# Проверки шага 1

Приложение поставляется тремя файлами: index.html, style.css, script.js. Тестовый инструмент не загружается приложением; сервер в тесте работает только на loopback и нужен для изолированного браузерного origin.

## Воспроизведение

Нужны Node.js 20+ и отдельная тестовая установка Playwright:

```sh
npm install --no-save --package-lock=false playwright@1.62.1
npx playwright install --with-deps chromium firefox webkit
node --check script.js
node test-stage1.cjs
TEST_BROWSER=firefox TEST_ARTIFACTS=test-results/firefox node test-stage1.cjs
TEST_BROWSER=webkit TEST_ARTIFACTS=test-results/webkit node test-stage1.cjs
```

На Linux Chromium берётся из /usr/bin/chromium, если доступен, иначе из Playwright. Путь можно задать CHROMIUM_PATH. Аналогично WEBKIT_PATH и FIREFOX_PATH. Служебные пути не используются приложением.

Исторический пример из handoff не включается в публичный репозиторий. Для дополнительной сверки:

```sh
STUDY_REFERENCE=/path/to/study-planner-2026-11-03.json node test-stage1.cjs
```

Без STUDY_REFERENCE запускаются 30 групп синтетических тестов, с ним — 31. Результаты JSON содержат версии браузеров, SHA-256 трёх проверенных исходников, названия групп, результат и время. Скриншоты создаются для телефона, планшета, десктопа, редактора и календаря. При ошибке процесс возвращает ненулевой код.

Тесты создают только новые браузерные контексты и синтетические записи. Они не открывают GitHub Pages, не читают браузерный профиль владельца, не очищают его localStorage и не обращаются к API/CDN из приложения.

## Ограничения

Playwright WebKit в Linux не является физическим iPhone или выпуском Safari. Автоматизация не подтверждает субъективное удобство и поведение экранной клавиатуры iOS. Одновременная запись нескольких вкладок не поддерживается: обнаруженные конфликты блокируются; localStorage не предоставляет compare-and-swap.

# Проверки шага 2

Приложение по-прежнему использует только три runtime-файла и не требует npm. Playwright — исключительно инструмент разработчика.

```sh
node --check script.js
node test-stage2-domain.cjs
TZ=Europe/Berlin node test-stage2-domain.cjs
TZ=Europe/Moscow node test-stage2-domain.cjs
TZ=Australia/Lord_Howe node test-stage2-domain.cjs
node test-stage2-browser.cjs
TEST_BROWSER=firefox node test-stage2-browser.cjs
TEST_BROWSER=webkit node test-stage2-browser.cjs
```

Расчётный набор — 23 теста на часовой пояс, включая 52 варианта интервала. Браузерный набор — 29 групп на движок; управляемые часы позволяют проверить паузы, 13-часовой порог, перевод часов и переход суток без ожидания реальных часов. Отдельный тест закрывает и заново запускает настоящий процесс браузера с временным постоянным профилем; реальные профили владельца не используются. TEST_ONLY позволяет запустить одну группу по части названия, полная приёмка выполняется без него.

Перед выпуском также выполнить test-stage1.cjs в трёх движках. Это прежние 31 группы регрессии; добавлен только переход в «Обучение» после первого запуска, поскольку стартовым экраном шага 2 стала главная.

Результаты и SHA-256 трёх исходников сохраняются в test-results-stage2/<browser>/results.json; скриншоты находятся рядом. Контексты изолированы; сеть приложения ограничена тремя файлами на loopback HTTP-origin. Таймерные и календарные данные в экспорте проверяются программно.

Ограничения автоматизации: физический iPhone/Safari, экранная клавиатура и удобство; выгрузка процесса операционной системой, очистка/эвикция хранилища и изменение часов/часового пояса самим устройством. Такие аппаратные и системные события не выдаются за подтверждённые тестом браузерной перезагрузки. Web Locks усиливает сериализацию таймерных действий, но общую атомарность localStorage при всех возможных гонках не гарантирует.

## Шаг 3 и актуальная регрессия

Среда: Linux, Node.js и установленный Playwright. Приложение по-прежнему не требует npm или сборки. Используются отдельные браузерные контексты, синтетические данные и временные профили; реальное хранилище пользователя не открывается.

```bash
node --check script.js
TZ=UTC node test-stage2-domain.cjs
TZ=UTC node test-stage3-domain.cjs
# Повторить оба расчётных набора для Europe/Berlin, Europe/Moscow, Australia/Lord_Howe.
node test-stage1.cjs
node test-stage2-browser.cjs
node test-stage3-browser.cjs
# Повторить с TEST_BROWSER=firefox и TEST_BROWSER=webkit.
```

`TEST_ARTIFACTS` задаёт отдельный каталог результатов, `TEST_ONLY` — адресный прогон браузерных наборов шагов 2/3. Для проверки исторического экспорта передать `STUDY_REFERENCE` с путём к собственному тестовому файлу; файл не добавляется в репозиторий. Без него регрессия шага 1 содержит 30 групп, с ним — 31. Для Chromium можно задать `CHROMIUM_PATH`, для Firefox/WebKit — `FIREFOX_PATH`/`WEBKIT_PATH`. В текущей Linux-среде WebKit запускается через `/workspace/browser-deps/run-webkit.sh` с локальными системными библиотеками в `LD_LIBRARY_PATH`; это настройка среды, не приложения.

`test-stage3-domain.cjs` проверяет формулы, области, границы периодов, архив, будущие повторения, объединение, конфликтное Undo и поиск. `test-stage3-browser.cjs` проверяет интерфейс, сохранение, отказы записи, импорт, темы/ОС, бэкапы, очистку, фильтры и мобильные ширины; сохраняет JSON с SHA256 трёх runtime-файлов и снимки экрана. Итоговые результаты и ограничения — `STAGE3_ACCEPTANCE.md` и `test-evidence/stage3/results.json`.

## Уточнение «курс → модули → занятия»

```bash
TZ=UTC node test-course-workflow-domain.cjs
node test-course-workflow-browser.cjs
# Повторить расчётный набор в четырёх зонах, браузерный — в Chromium/Firefox/WebKit.
```

Дополнительно повторяются все три прежних набора. Регрессия структуры выбирает `learningMode=tree`; регрессия таймера включает `showTimeTracking=true`, поскольку основной интерфейс теперь скрывает необязательный учёт времени. Новый набор работает с `learningMode=courses`, `showTimeTracking=false` и проверяет курс, модули до занятий, цель, сроки, иконки, импорт, архив, Undo, ошибки записи и четыре ширины. Расчётный набор проверяет точную долю шагов, полный конечный план повторений и безопасный упаковщик личной копии. Новые результаты — `test-evidence/course-workflow/`.

Личный HTML создаётся **вне репозитория**, например:

```bash
node build-personal-copy.cjs /private/path/to/backup.json /private/path/to/output
```

Выход содержит персональные записи, его нельзя добавлять в публичный GitHub. При существующем ключе localStorage личный комплект ничего автоматически не заменяет; объединение требует явного подтверждения.

## Программа курса

Новые наборы: `test-course-program-domain.cjs` (6 расчётных групп) и `test-course-program-browser.cjs` (8 браузерных групп). Повторить в четырёх часовых поясах и трёх движках вместе с прежними наборами. Они проверяют массовое сохранение программы, пустые/частично заполненные модули и резерв количества, неправильные даты/URL/ID/числа, отсутствие автосохранения промежуточного плана, отказ хранилища, отмену черновика, экспорт/замену/объединение, экзамен/дни недели и предложение даты, мобильную ширину и клавиатуру. Все данные синтетические. Актуальный отчёт — `test-evidence/course-program/results.json`.
