# Техническое задание: «Мой учебный планировщик»

**Редакция:** 3.1, 02.11.2026  
**Основание:** исходное ТЗ v3.0 от 22.10.2026 и `plan.md` (4 шага).  
**Статус:** уточнённая спецификация и контрольный лист перед шагом 2.  
**Приоритет:** требования этого документа об изменённой иерархии и привязке заданий имеют преимущество над противоречащими формулировками v3.0. Все остальные требования v3.0 сохраняются.

## 1. Цель и технические ограничения

Однопользовательский офлайн-планировщик обучения на русском языке. Три исходных файла приложения: `index.html`, `style.css`, `script.js`. Нативные HTML/CSS/JS, без сборки, библиотек, CDN, API, сервера, БД, авторизации и синхронизации. Хранение в `localStorage` конкретного браузера и origin, ключ `studyPlanner:v1`; сохранение на одном устройстве не означает синхронизацию с другим. Поддерживать резервные копии JSON с проверкой целостности. Интерфейс адаптивный и доступный с клавиатуры и касания.

## 2. Изменённая структура обучения (обязательное изменение)

**Направление → Предмет → Курс преподавателя → Тема → Занятие → Задания.**

- Направление - большая область развития (например, финансовое моделирование).
- Предмет - дисциплина внутри направления (например, управленческий учёт).
- Курс преподавателя - отдельная учебная программа с собственными темами и занятиями. Разные программы по одному предмету независимы.
- Тема - тематический раздел конкретного курса.
- Занятие - самостоятельная единица планирования: лекция, практика, самостоятельное обучение, вебинар; дата, время, длительность, статус, конспект и ссылки.
- Задание - **обязательно связано с одним занятием**, не может существовать только на уровне темы. Одно занятие может иметь 0, 1 или несколько заданий. Задание содержит описание, срок, приоритет, ответ, заметки, ссылки и шаги выполнения.

### Обязательное поведение интерфейса

1. Кнопка «+ Задание» располагается **внутри конкретного занятия**; не создавать задания непосредственно под темой.
2. При открытии занятия отображаются его задания, их статусы и прогресс. Можно создать, изменить, удалить, отметить шаги и открыть ответ.
3. Общий раздел «Задания» остаётся как агрегированный список всех заданий, но каждое задание показывает путь до занятия. При создании из общего списка необходимо выбрать конкретное занятие.
4. В мобильной версии дерево сворачивается/разворачивается на каждом уровне; открытие одного узла не должно раскрывать весь длинный список. Состояние сворачивания желательно сохранять.
5. Для курса преподавателя предусмотреть название, преподавателя, описание и принадлежность предмету. Независимость программ гарантируется отдельными идентификаторами.
6. Перемещение, архивирование, восстановление и каскадное удаление сохраняют ссылочную целостность. Удаление занятия затрагивает связанные с ним задания, с явным подтверждением.

## 3. Модель данных и миграция

- Добавить `subjects[]` и связь `subject.directionId`.
- `courses[]` должны ссылаться на `subjectId`, а также содержать информацию о преподавателе.
- `topics[]` связаны с `courseId`, `sessions[]` - с `topicId`, `homeworks[]` - с **обязательным** `sessionId`.
- `topicId` в записи задания допускается только как вычисляемая/совместимая ссылка и должен совпадать с темой выбранного занятия; источником истины является `sessionId`.
- Ввести новую версию схемы и безопасную миграцию данных из `schemaVersion:1`. Нельзя просто отклонить старый `localStorage` или стереть его.
- Для существующих курсов автоматически создать предмет-посредник с понятным названием (например, «Без предмета») и привязать курс к нему, сохранив исходные ID курсов, тем и занятий.
- Для старых заданий с `sessionId` сохранить существующую связь. Для заданий без `sessionId` **не выбирать занятие случайно**: поместить их в отдельный список «Требуют привязки», не удалять и не скрывать без уведомления. До привязки такие записи остаются доступны для редактирования и экспорта.
- Перед миграцией предложить экспорт исходного JSON; миграцию выполнять на копии состояния, валидировать и записывать атомарно. При ошибке исходные данные не менять. Обеспечить идемпотентность миграции.
- Импорт старых резервных копий должен использовать ту же безопасную миграцию. Не изменять формат данных молча без тестов.

## 4. Шаг 1 - обновлённые критерии готовности

В исходном плане шаг 1 включает три файла, навигацию, стартовые направления, CRUD и дерево, разовые занятия четырёх типов, задания с шагами и процентом, конспекты/ответы/ссылки, редактор, валидации, локальное сохранение, календарь (сегодня/неделя/месяц/список), экспорт JSON и импорт с полной заменой. Дополнительно обязательны изменения разделов 2-3 этого документа.

**Проверки до приёмки:**

1. Создать направление → предмет → курс преподавателя → тему → два занятия → по два задания на каждое; проверить отсутствие заданий на уровне темы.
2. Проверить независимость двух курсов преподавателей по одному предмету.
3. Проверить шаги заданий: 0%, частичный процент, 100%, снятие отметки, `completedAt`; сохранить и перезагрузить страницу.
4. Проверить создание/редактирование/удаление, архив и восстановление всей вложенной структуры, перемещение и запрет осиротевших ссылок.
5. Проверить текст, URL http(s), блокировку `javascript:`, защиту от HTML-инъекций и валидацию полей.
6. Проверить календарь: 4 вида, переход дат, создание из слота, пересечения и занятие через полночь.
7. Проверить на телефоне сворачивание каждого уровня и удобство редактора, без потери введённых данных.
8. Проверить сохранение после перезагрузки, экспорт → импорт, ошибочный JSON, отказ хранилища и миграцию существующих данных.
9. Проверить браузерную консоль и отсутствие ошибок JS, сохранение всех связей, а также работу на реальном мобильном экране.

**Правило:** проверка наличия функций в исходном коде не равна успешному функциональному тесту. Без пройденной регрессии шаг 1 не принят.

## 5. Шаг 2 - планирование, таймер и главная

**Состав исходного шага 2 без расширения:**

- Повторения ежедневно, еженедельно по выбранным дням, каждые N дней/недель; обязательная конечная дата, ограничение 2 года/1000 вхождений, генерация только в видимом диапазоне.
- Перенос/отмена одного вхождения и изменение серии с подтверждением и сохранением истории.
- Внутристраничные напоминания, без фоновых push-уведомлений.
- Таймер «Старт / Пауза / Продолжить / Завершить / Отменить», точный учёт активных секунд, сохранение при перезагрузке, предупреждение после 12 часов, защита от конфликтов вкладок.
- Главная: шесть блоков «Сегодня», «Дедлайны», «Прогресс», «Неделя», «Цели», «Быстро добавить». Нереализованные до шага 3 показатели целей не выдавать за реальные.
- Быстрое добавление через общий редактор, сохранение порядка блоков главной кнопками «Вверх/Вниз».

**Проверки:** ежедневные/недельные/кастомные правила и DST; отсутствие дубликатов; история при переносе; таймер с паузой и перезагрузкой; 12-часовой порог и конфликты вкладок; корректность шести блоков и их порядка; полная регрессия шага 1 с новой иерархией.

## 6. Шаги 3-4 (сохраняются)

Шаг 3: цели четырёх типов, аналитика план/факт, поиск и фильтры, объединение импорта, 10-секундная отмена удаления, светлая/тёмная/системная темы, напоминание об экспорте, полные настройки и диагностика, завершение блоков главной.

Шаг 4: сквозная приёмка, исправления дефектов, мобильная/планшетная адаптация, доступность, производительность, тесты всех обязательных сценариев и сохранения/импорта. Никаких дополнительных функций сверх ТЗ.
