# Study Planner — учебный планировщик

**Публичное приложение:** https://study-planner-coursework-public-20261108.fondlyric2.chatgpt.site

**Исходный код:** https://github.com/sheninaliudmila-afk/study-planner

Учебная работа: разработать планировщик по ТЗ, проверить результат, загрузить на GitHub и опубликовать. Итоговая проверка нейросетью и ограничения проверки: [PUBLIC_SUBMISSION.md](PUBLIC_SUBMISSION.md).

## Возможности

- Направления → предметы → курсы → модули/темы → занятия → домашние задания.
- Группировка курсов по направлениям, перенос курса вместе с материалами, сроки обучения и дополнительные дедлайны.
- Конспекты до 100 000 символов, внешние ссылки на документы, ручное подтверждение прохождения модуля.
- Календарь, повторения и исключения, задания с прогрессом по шагам, цели, аналитика и поиск.
- Главная с активными курсами и расписанием, необязательный таймер, архив и отмена удаления.
- JSON-экспорт, проверяемый импорт и объединение, безопасная миграция старой схемы, обработка квоты и конфликтов вкладок.
- Мобильный интерфейс, клавиатура, светлая/тёмная/системная темы.

## Как пользоваться

Откройте публичное приложение. Создайте направление и курс, заполните программу модулей и добавьте занятия. Новый посетитель начинает со своей пустой базы и стартовыми направлениями. Конспекты и записи разных посетителей не объединяются: они хранятся в localStorage конкретного браузера и адреса, ключ `studyPlanner:v1`.

Вход и сервер приложения не нужны. Для переноса между браузерами используйте «Настройки» → «Экспорт JSON», затем импорт в нужном браузере. GitHub Pages не синхронизирует записи. Личная программа владельца и его конспекты в публичную сборку не включены.

## Запуск и размещение

Runtime — ровно три файла: `index.html`, `style.css`, `script.js`. Нативные HTML/CSS/JavaScript, без сборки, CDN, библиотек и API. Для статического хостинга файлы должны лежать в одной папке. `.nojekyll` подготовлен на случай последующего включения GitHub Pages. Публичный сайт сейчас размещён отдельно через Sites.

Можно открыть `index.html` локально; сохранение при `file://` зависит от браузера. Для устойчивого адреса используйте публичную HTTPS-версию. [Инструкция](START_HERE_RU.md) описывает локальный HTML и резервные копии. Прочие файлы репозитория — документация, тесты и средства подготовки поставки, они не требуются приложению для работы.

## Проверки

**637 проверок пройдено:** 369 браузерных групп в Chromium/Firefox/WebKit, 268 расчётных случаев в четырёх часовых поясах. [Машинный отчёт](test-evidence/grouping-release/results.json), [аудит](AUDIT_STATUS.md), [план](plan.md), [протокол](GROUPING_RELEASE_ACCEPTANCE.md).

WebKit проверен автоматически; это не ручная проверка настоящего Safari/iPhone/VoiceOver. Ограничения перечислены в итоговом отчёте. Исходники публичной версии совпадают с SHA256 проверенных runtime-файлов.

Основное ТЗ: [3.0](requirements/tz.md), [уточнения 3.1](requirements/tz_study_planner_v3_1.md). Последующие поручения владельца в requirements/ уточняют интерфейс и прогресс курсов. Старые протоколы и исторические статусы отражают свои даты; текущий результат — PUBLIC_SUBMISSION.md.

GitHub Pages не включён: подключение вернуло HTTP 403 «Resource not accessible by integration» при создании Pages, несмотря на доступ к коду. Это ограничение подключения, а не ошибка приложения. Публичный сайт доступен по ссылке выше; код находится в main.
