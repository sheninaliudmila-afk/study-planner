# Программа курса: проверка от 08.11.2026

Основание: [последнее уточнение](requirements/course-program-2026-11-08.md). Ветка `stage3-goals-analytics-settings-2026-11-08`, [PR №2](https://github.com/sheninaliudmila-afk/study-planner/pull/2).

## Готово

Единый редактор всех модулей: названия, даты, сроки и количество занятий; начало обучения, экзамен, дедлайн, ссылка на платформу и дни недели. Целостное сохранение после явного подтверждения кнопкой. Введённое количество учитывается в прогрессе до заполнения отдельных занятий. Существующие записи и их ID не удаляются при изменении плана. Новые занятия не создаются по одному только числу.

Дни недели предлагают ближайшую подходящую свободную дату в редакторе занятия. Дата экзамена видна в курсе, календаре и внутристраничном напоминании. Ссылка на платформу допускает только http(s) без встроенных логина и пароля и открывается с noopener/noreferrer.

Прежние данные без новых необязательных полей по-прежнему загружаются с тем же ключом и схемой 2. Экспорт, замена, объединение, архив, удаление, Undo, таймер и прежние четыре метода целей сохранены.

## Что не выполнено и почему

**Получение реального расписания SohoLMS:** предоставленная страница открыла экран входа. Доступа к авторизации iPhone нет, поэтому названия, сроки и количества не извлечены и не придуманы. Нужен разрешённый доступ или сама программа (документ/снимки списка модулей). Универсальный автоматический импорт из закрытых платформ не реализован и не изображается рабочей кнопкой.

Физические Safari/iPhone, VoiceOver и реальное сохранение в папку устройства недоступны для проверки в этой Linux-среде. Прямой file:// в управляемом Chromium заблокирован политикой среды. WebKit Linux не считается Safari iOS. Строгая атомарность всех гонок localStorage не обещается.

## Тестовая площадка

Существующая закрытая площадка: адрес передан владельцу в личном чате . Размещается общий код без личного JSON и восстановленного HTML. Пробные записи хранятся в localStorage браузера по этому же адресу; изменение версии не включает очистку данных. GitHub main и основной сайт не изменяются; PR не сливается. Шаг 4 остаётся отдельной сквозной приёмкой.
